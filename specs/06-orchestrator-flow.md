# Spec 06 — 主 Agent 的逐项委派

群聊中的 `isOrchestrator: true` 成员是主 Agent。会话服务将群聊发送、编辑重发和重新生成统一路由给它。单聊直接启动会话唯一的 Agent。旧消息中的提及字段可随历史读取，转发入口按会话角色选择 Agent。

## 执行流程

1. 主 Agent 通过 AgentRunner 和现有模型适配器回复，使用自己配置的工作区和产物工具直接执行。内置主 Agent 默认具备文件读写、命令执行、产物和部署工具。有子 Agent 时，适配器额外提供 `delegate_task`，运行器在提示中列出可用成员。
2. 主 Agent 提交一项任务。后端校验成员、任务描述和参考产物的会话归属。
3. 单项 LangGraph 进入审批。用户批准后创建子 Run，拒绝或修改意见作为结果交回主 Agent。审批接口见 [Spec 17](./17-orchestrator-plan-review.md)。
4. 子 Agent 在独立消息上下文中运行，输入是任务及指定的产物 ID。它使用自己的模型、工具配置和会话工作区。
5. 子 Run 完成后，原工具调用返回状态、限长摘要、错误和产物 ID。模型拿到工具结果后决定继续委派或向用户作答。

每个模型响应最多接受一次委派。同一主 Run 内，前一项结束后才进入下一轮决策。父 Run 中止时，清理待审批项并向已启动的子 Run 传递中止信号。

主 Agent 直接调用工具时，适用当前会话的工作区边界和工具审批。服务启动时升级由旧版内置主 Agent 默认生成的只读工具清单，用户自行配置的清单继续生效。

## 消息与任务卡

SSE 通过主消息 ID 关联每项委派的审批和进度。委派工具调用与结果保存在主消息的 parts 中，子消息保存在对应的子 Run 下。消息快照从 Run 关系提供 `parentRunId`，前端用它将子消息归入任务详情。主 Agent 的历史上下文从顶层消息构建。

后端入口在 `backend/app/runner/agent_runner.py`。单项审批和执行节点在 `backend/app/runner/orchestration_graph.py`。工具结果由适配器送回当前模型工具循环。
